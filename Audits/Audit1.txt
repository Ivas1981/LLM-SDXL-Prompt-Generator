**Аудит проекта [LLM-SDXL-Prompt-Generator](https://github.com/Ivas1981/LLM-SDXL-Prompt-Generator)** (состояние на момент проверки, версия ~1.1.0 от 2026-09-02).

Проект — локальный Python-инструмент, который через LM Studio гоняет локальную LLM по 8-шаговому пайплайну и генерирует батчи SDXL-промптов (positive + negative) с проверкой уникальности через embeddings. Архитектура модульная, акцент на строгий JSON, очистку quality-bait тегов и атомарную запись.

### Сильные стороны
- Чёткое разделение ответственности: `core/pipeline.py` оркестрирует шаги, `validator.py` — единственный источник сборки финальных промптов, `lm_client.py` — работа с LM Studio (native + OpenAI-compat endpoints).
- Хорошая обработка edge-cases: atomic save (`tempfile` + `os.replace`), безопасный Ctrl+C, retry с логами причин, cache embeddings, architecture-aware sampling presets, `reasoning="off"` для reasoning-моделей.
- Consistency-проверка environment (время суток / погода / location без leaks).
- Запрет appearance-тегов + `{prompt}`-placeholder — правильный подход для reusable appearance.
- Тесты есть (unittest, ~73 по changelog), debug-логирование подробное.
- README + README_RU + CHANGELOG на двух языках.

### Ошибки, неточности и логические несоответствия

1. **Дублирование в README**  
   Features дважды перечисляют «Cross-field and within-field tag deduplication» и «Retry reason logging…». Мелочь, но выглядит неаккуратно.

2. **Шаг 4 (state) жёстко заточен под nudity**  
   User-hint и system-prompt (`step4_state.txt`) явно требуют «partial or full nudity». Это делает весь генератор ориентированным на NSFW/эротический контент. Если цель — общий SDXL-генератор, это логическое несоответствие (и потенциально ограничивает применимость). В README это не заявлено явно.

3. **FORBIDDEN_TAGS слишком агрессивны**  
   В `config.py` запрещены `woman/girl/female/...`, все цвета волос, типы телосложения, расы, возраст.  
   - Это логично для `{prompt}`-placeholder, но при ошибке LLM (или если пользователь хочет полный промпт без placeholder) теги просто вырезаются.  
   - В negative-prompt `FORBIDDEN_TAGS_NEGATIVE` пустой — нормально, но стоит документировать.

4. **Сборка negative_prompt**  
   `assemble_negative` добавляет только базовые теги + контекстные противоположности (daylight для night, urban для nature и т.д.).  
   Логика хорошая, но:
   - Нет динамических «противоположностей» для pose/state/clothing.
   - Базовый список довольно короткий (можно добавить распространённые SDXL-артефакты: `extra digits`, `mutated hands`, `text`, `watermark`, `lowres` и т.п.).

5. **Проверка уникальности**  
   - Точное совпадение prompt + semantic similarity по concept (subject+pose+state+environment).  
   - Threshold 0.85 по умолчанию — разумно, но при большом количестве сцен embedding-модель `all-minilm-l6-v2` может давать шум.  
   - Если embedding-модель недоступна — gracefully деградирует только до exact-match (хорошо), но пользователь может не заметить.

6. **Naming (step8)**  
   `_safe_name` + retry + numeric suffix — работает.  
   Но fallback из subject/environment может давать очень длинные или странные имена.  
   Проверка конфликтов смотрит `endswith("_" + scene_name)` — может ложно срабатывать на похожих именах.

7. **Зависимости и окружение**  
   - `requirements.txt` содержит только `requests>=2.28`. Нет `tomllib`/`tomli` (хотя config.toml используется). В Python 3.11+ `tomllib` есть в stdlib, но для 3.10- нужно явно.  
   - Нет `pyproject.toml` / `setup.cfg` / lock-файла.  
   - Нет указания минимальной версии Python.

8. **Конфигурация**  
   Приоритет (env > config.toml только для lm_studio.* > defaults) заявлен, но в коде `config_loader` и `env_registry` немного размазаны.  
   `EMBEDDING_MODEL_NAME` в registry есть, но в runtime перезаписывается интерактивным выбором — нормально, но документация могла бы быть яснее.

9. **Пайплайн**  
   - Step1–7 идут последовательно, при падении любого шага вся сцена отбрасывается (max_attempts = target × 10). При «капризной» модели это может приводить к большому числу бесполезных вызовов.  
   - Step7 (assemble) имеет низкую temperature (0.2) — правильно, но если LLM всё равно выдаёт prose, `validate_result` отбракует.  
   - В `STEP_USER_HINT` для step4 явно «partial or full nudity» — см. п.2.

10. **Мелкие технические моменты**  
    - В `lm_client.py` есть `requests.compat.json` — устаревший/нестандартный путь (лучше `json` напрямую).  
    - `debug_log` и некоторые импорты используют динамический `sys.path.insert` — работает, но хрупко.  
    - Нет type hints в некоторых местах, нет mypy/ruff-конфига.

### Рекомендации и улучшения

**Критичные / высокоприоритетные**
- Сделать nudity/опциональный NSFW-режим конфигурируемым (флаг `NSFW_MODE=true/false` или отдельный набор system-prompts). Сейчас генератор фактически NSFW-only.
- Расширить `NEGATIVE_BASE_TAGS` более полным стандартным SDXL-набором + дать возможность полностью переопределять через env/config.
- Добавить `pyproject.toml` (или хотя бы `requirements.txt` с `tomli` для <3.11 и указанием `python_requires`).
- Убрать дубли в README и явно указать целевую аудиторию/ограничения (NSFW bias, зависимость от LM Studio, English-only prompts).

**Качество промптов и пайплайна**
- Добавить cross-field consistency checks не только для environment, но и для pose ↔ state ↔ lighting (например, «lying down» + «standing lighting»).
- В step7 жёстче требовать, чтобы `{prompt}` был **только** в subject и не появлялся в других полях.
- Сделать temperature/max_tokens per-step настраиваемыми через config.
- После сборки прогонять финальный positive через простой post-processor (удаление повторов, нормализация порядка тегов: subject → clothing/pose → state → environment → lighting → camera).

**Архитектура и DX**
- Вынести все system-prompts в один YAML/JSON со схемами (сейчас 8 отдельных .txt — удобно редактировать, но сложнее валидировать).
- Добавить dry-run / `--prompt-only` режим без реальных вызовов LLM (для тестов).
- Поддержка нескольких embedding-моделей + возможность отключать semantic-check полностью через флаг.
- Логировать не только retry reasons, но и итоговую статистику (успешность по шагам, среднее число попыток, распределение similarity).
- CLI через `argparse`/`typer` вместо чистого interactive (target count, model, embedding уже выбираются интерактивно — хорошо, но для скриптов нужен non-interactive режим).

**Тесты и надёжность**
- Добавить integration-тесты с mock LM Studio (сейчас в основном unit).
- Проверять, что после `remove_forbidden_tags` + `remove_quality_bait` + dedup промпт остаётся валидным и содержит `{prompt}`.
- Тест на коллизии имён при большом количестве существующих записей.

**Документация**
- Пример выходного JSON.
- Рекомендуемые модели (какие LLM лучше работают с JSON-only + низкими temperature).
- Как правильно использовать `{prompt}` в Automatic1111 / ComfyUI / Forge.
- Известные ограничения (зависимость от качества локальной LLM, английский only, NSFW bias).

### Итоговая оценка
Проект уже на хорошем уровне зрелости для «личного инструмента»: модульный, с вниманием к edge-cases, retry, atomic I/O и debug. Основные проблемы — жёсткая NSFW-ориентация (не задокументирована), слишком агрессивный forbidden-list и минимальные зависимости/дистрибуция. После исправления README-дублей, выноса nudity в опцию и небольшого расширения negative/consistency логики станет заметно сильнее.

Если нужно — могу точечно предложить патчи (diff) для конкретных файлов или помочь с конкретным улучшением.
